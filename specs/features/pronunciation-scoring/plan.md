# Pronunciation Scoring — Plan

## 為什麼做

現有學習迴路缺「產出」環節：學習者能看（插圖）、能聽（音檔）、能寫（筆順）、能認（聽力測驗），
但**唸得對不對沒有任何回饋**。發音評分補上這塊，也讓「精熟度」有真正值得給分的硬任務
（呼應 `game-system` R8 的設計：探索是麵包屑不給分，精熟留給發音評分）。

## 分階段

| 階段 | 目標 | 評分引擎 |
|------|------|---------|
| **Phase A（本次）** | 驗證錄音 → 評分 → 回饋 → UI 的**流程與體感**好不好玩 | Gemini（已有額度，快速原型） |
| Phase B（之後） | 上線品質的精準評分 | Azure Speech Pronunciation Assessment |

> ⚠️ Phase A 的評分**不可靠**（Gemini 非訓練過的發音評分器，聲調/音準判斷不準，
> 兒童聲音更不準）。本階段只驗證流程，不驗證評分準確度。

## Phase A 範圍

- **獨立測試頁 `/pronounce`**（不動現有頁面，零風險）
- 選一個例詞 → 聽範例 → 錄音 → 送 Gemini → 顯示「分數 + 一句回饋」
- 首頁不放入口（測試用，直接打網址進入）

## 不在範圍內

- 精準評分（Phase B 換 Azure）
- 接積分系統（流程驗證通過後再說）
- 正式上線（此功能不卡現有上線範圍）

## 已知的架構影響（Phase B 才觸發）

Azure 需要密鑰，**密鑰不能放前端** → 屆時需要第一個後端（Vercel Serverless Function 代理）。
Phase A 用 Gemini 也有同樣問題，但原型階段先用現有的 `.env` key 在本機測試，不部署。

## 隱私考量

目標用戶含兒童，錄音上傳第三方涉及隱私：
- 錄音**只即時評分、不儲存**（記憶體處理完即丟）
- Phase B 上線前需補家長同意說明
